# Финик — бэкенд

Серверная часть детского приложения по финансовой грамотности. Сервер считает правила игры,
мобильный клиент показывает состояние и отправляет действия. План и разбор идей — в PLAN.md.

## Запуск локально

Нужны PostgreSQL 15+ и uv.

```bash
brew services start postgresql@15
createdb finik && createdb finik_test
cp .env.example .env
uv sync --all-groups
make migrate
make seed
make dev
```

Документация API: http://localhost:8000/docs

## Команды

| Команда | Что делает |
|---|---|
| `make dev` | API с автоперезагрузкой на порту 8000 |
| `make migrate` | применить миграции |
| `make revision m="описание"` | создать миграцию по изменённым моделям |
| `make seed` | заполнить справочники: лавка, задания, уроки, достижения, события |
| `make test` | все тесты на базе finik_test |
| `make lint` | ruff: проверка и формат |

Через Docker: `docker compose up --build`, миграции применятся сами.

## Архитектура

Четыре слоя, зависимости направлены внутрь: api → application → domain ← infrastructure.

```
src/
├── domain/          правила игры на чистом Python, без FastAPI и SQLAlchemy
│   ├── enums.py     виды ростков, статьи плана, настроение
│   ├── rules.py     все числа баланса в одном месте
│   ├── entities.py  Player, Pet, Week, PlanEntry, Goal, LogEntry
│   └── services/    planning (план), care (уход), growth (день и неделя)
├── application/     сценарии и порты
│   ├── ports.py     протоколы репозиториев и единицы работы
│   ├── dto.py       что сценарии отдают наружу
│   └── use_cases/   onboarding, gameplay
├── infrastructure/  реализация портов
│   └── db/          engine, ORM-модели, репозитории, mappers, uow
├── api/             FastAPI: зависимости, схемы, роутеры v1
└── main.py          сборка приложения и обработчик ошибок
```

Правила лежат в `domain/services` и тестируются без базы (`tests/domain`). Сценарии в
`application/use_cases` открывают одну транзакцию, вызывают правила, пишут журнал и коммитят.
Репозитории переводят строки базы в сущности домена и обратно через `mappers.py`; ORM-модели
наружу не выходят. Ошибки домена наследуют `AppError` и превращаются в ответ
`{"error": {"code", "message"}}` одним обработчиком.

## Цикл игры

Игровая неделя из семи дней. Доход приходит в начале недели свободными монетами, ребёнок
раскладывает их по статьям: Еда, Вода, Игры, Копилка. Уход за ростком списывает монеты из своей
статьи. Если в статье еды или воды пусто, монеты берутся из копилки, и это перерасход. День
завершается явным действием: потребности убывают, начисляется опыт. На седьмом дне неделя
закрывается: копилка уходит в мечту, остатки статей возвращаются, приходит новый доход.

## API v1

| Метод | Путь | Что делает |
|---|---|---|
| POST | `/auth/device` | токен по идентификатору устройства |
| POST | `/pet` | создать ростка: имя, вид, доход |
| GET | `/state` | полное состояние игры |
| PUT | `/plan` | распределить монеты по статьям |
| POST | `/care` | полить, покормить или поиграть |
| POST | `/goal/deposit` | отложить свободные монеты в мечту |
| POST | `/day/end` | завершить день, на седьмом закрыть неделю |
| GET | `/shop/items` | витрина: остаток в статье и доступность |
| POST | `/shop/buy` | купить товар из своей статьи |
| GET | `/tasks` | задания недели с прогрессом |
| GET | `/tasks/{slug}/questions` | вопросы мини-урока, без правильных ответов |
| POST | `/tasks/{slug}/answer` | ответить на вопрос, получить объяснение |
| POST | `/tasks/{slug}/claim` | забрать награду за выполненное задание |
| GET | `/weeks/history` | закрытые недели и отчёт план/факт последней |
| GET | `/events/today` | событие дня с вариантами выбора |
| POST | `/events/{id}/choose` | сделать выбор, получить последствия и объяснение |
| GET | `/profile` | итоги за всё время и настройки |
| PATCH | `/profile` | доход в неделю, звуки |
| GET | `/profile/badges` | достижения с процентом выполнения |
| POST | `/profile/reset` | начать заново, токен остаётся |

Все пути с префиксом `/api/v1`, кроме `/health`. Авторизация: `Authorization: Bearer <token>`.

## Таблицы

Игровые: `players`, `pets`, `weeks`, `plan_entries`, `goals`, `action_log`, `purchases`,
`task_progress`, `player_badges`, `event_instances`.
Контент, заполняется сидом: `shop_items`, `task_defs`, `quiz_questions`, `badge_defs`,
`event_defs`.

## Контент

Справочники лежат кодом в `src/infrastructure/content/catalog.py` и заливаются командой
`make seed`. Повторный запуск обновляет строки, не плодя дублей. Задания оцениваются по фактам
недели в `domain/services/tasks.py`: урок по верным ответам, накопление по вкладам и копилке,
привычка по дням с уходом, покупка со скидкой по журналу покупок.

## События

Одно событие на игровой день. Выбор события детерминирован хешем от игрока, недели и дня,
поэтому повторный запрос даёт то же самое. Варианты и последствия описаны в каталоге полем
`effects`: `coins` меняет свободные монеты, `cost` списывает из статьи, `need` двигает
потребности, `xp` даёт или отнимает опыт, `note` объясняет ребёнку, что произошло. Правило
не даёт уйти в минус: мошеннику нечего перевести, если свободных монет нет.
