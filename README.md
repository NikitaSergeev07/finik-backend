# Финик — бэкенд

Серверная часть детского приложения по финансовой грамотности. Сервер считает правила игры,
мобильный клиент показывает состояние и отправляет действия. Согласованные правила интеграции сохранены в `Finik/docs/integration-spec.md` Android-проекта. `PLAN.md` содержит исторический план и может отличаться от новых правил.

## Запуск локально

Нужны PostgreSQL 15+ и uv. В текущей локальной среде используется Postgres.app на `localhost:5433`, база `finik`. Подключение и ключи задаются в `.env` (файл не входит в git).

```bash
uv sync --all-groups --frozen
uv run alembic upgrade head
PYTHONPATH=src uv run python -m infrastructure.content.seed
uv run uvicorn main:app --app-dir src --reload --host 127.0.0.1 --port 8000
```

В PyCharm выберите интерпретатор `.venv/bin/python` и сохранённую конфигурацию **Finik API** из `.run/Finik_API.run.xml`. PostgreSQL должен быть запущен отдельно. Документация: [Swagger](http://127.0.0.1:8000/docs).

Android Emulator обращается к компьютеру по `http://10.0.2.2:8000/`. Для физического телефона нужен доступный ему адрес сервера; релизный клиент принимает только HTTPS.

## Команды

| Команда | Что делает |
|---|---|
| `make dev` | API с автоперезагрузкой на порту 8000 |
| `make migrate` | применить миграции |
| `make revision m="описание"` | создать миграцию по изменённым моделям |
| `make seed` | заполнить справочники: лавка, задания, уроки, достижения, события |
| `make test` | тесты на отдельной базе `finik_test`, по умолчанию порт 5432 |
| `make lint` | ruff: проверка и формат |

Тесты пересоздают схему, поэтому им нужна отдельная база. Для локального Postgres.app на порту 5433 используйте:

```bash
make test TEST_DATABASE_URL=postgresql+asyncpg://localhost:5433/finik_test
```

`make test` задаёт тестовый DSN отдельно и не берёт адрес основной базы из `FINIK_DATABASE_URL` или `.env`.

Через Docker: запустите Docker Desktop, затем `docker compose up --build`. Compose поднимет отдельный PostgreSQL в контейнере, а команда запуска API применит миграции. Для новой базы загрузите контент:

```bash
docker compose exec api sh -c "PYTHONPATH=src uv run python -m infrastructure.content.seed"
```

`.dockerignore` исключает локальные `.venv`, `.env` и кэши из образа. Compose передаёт URL контейнерной базы и JWT-секрет через окружение. Ключи ИИ из локального `.env` автоматически в контейнер не передаются: при необходимости добавьте соответствующие переменные в `api.environment`. Сборка и запуск Docker в рамках этой интеграции не проверялись.

## Архитектура

Четыре слоя, зависимости направлены внутрь: api → application → domain ← infrastructure.

```
src/
├── domain/          правила игры на чистом Python, без FastAPI и SQLAlchemy
│   ├── enums.py     виды питомцев, статьи плана, настроение
│   ├── rules.py     все числа баланса в одном месте
│   ├── entities.py  Player, Pet, Week, PlanEntry, Goal, LogEntry
│   └── services/    planning, care, growth, persona, safety, words
├── application/     сценарии и порты
│   ├── ports.py     протоколы репозиториев, единицы работы и LLM
│   ├── dto.py       что сценарии отдают наружу
│   └── use_cases/   onboarding, gameplay, shop, tasks, events, ai
├── infrastructure/  реализация портов
│   ├── db/          engine, ORM-модели, репозитории, mappers, uow
│   └── ai/          клиент GigaChat и шлюз с заготовками
├── api/             FastAPI: зависимости, схемы, роутеры v1
└── main.py          сборка приложения и обработчик ошибок
```

Правила лежат в `domain/services` и тестируются без базы (`tests/domain`). Сценарии в
`application/use_cases` открывают одну транзакцию, вызывают правила, пишут журнал и коммитят.
Репозитории переводят строки базы в сущности домена и обратно через `mappers.py`; ORM-модели
наружу не выходят. Ошибки домена наследуют `AppError` и превращаются в ответ
`{"error": {"code", "message"}}` одним обработчиком.

## Цикл игры

Питомец — сова с шестью цветами и несколькими аксессуарами. Первый план пустой, доход свободен; можно подтвердить частичное распределение. Подтверждённый план разрешено только пополнять свободными монетами, без переносов между статьями.

Обычная неделя календарная: понедельник 00:00 — следующий понедельник 00:00 по IANA-часовому поясу игрока. Серверное время нельзя ускорить клиентским запросом. Ежедневное снижение потребностей и смена недель применяются при обращении к серверу. Первая неполная неделя получает полный доход; доход за пропущенные недели не накапливается. За каждые семь игровых дней выдаётся 5 монет без требования ежедневного посещения.

Уход даёт +22 потребности и +1 XP. При нехватке FOOD/WATER полная стоимость может списываться из SAVE с фиксацией перерасхода. Нулевые потребности ведут к потере XP и возможному откату стадии. В конце недели остатки FOOD/WATER/PLAY возвращаются в свободные монеты, остаток SAVE автоматически переводится в выбранную цель с бонусом 5%, округлённым вниз.

У трёх целей отдельные балансы. Ручной вклад после подтверждения плана списывается из SAVE. Снятие из цели пополняет PLAY. Изменение недельного дохода действует со следующей недели.

Цены растут на 5% исходного значения за неделю (предел +50%), количественные цели заданий — на 10% (предел ×2); награды растут медленнее. Небольшие снижения цен реализуются распродажей до 10% с округлением вверх, чтобы скидка дешёвого товара не превысила предел.

Демопрофиль отделён от обычного. Доступ пока открыт без кода, доступны сценарии `new` и `prepared`. Только демо разрешает переход на следующий день/неделю. Повторный явный выбор сценария создаёт соответствующее начальное демосостояние; обычный профиль не сбрасывается.

## Контент

Справочники лежат кодом в `src/infrastructure/content/catalog.py` и заливаются командой
`make seed`. Повторный запуск обновляет строки, не плодя дублей. После обновления кода
команду нужно запустить снова: она добавит три экспедиции, семь коротких игр, 21 игровой шаг и практические
задания. В сиде 16 товаров лавки двух типов (нужда / желание).
В играх ребёнок набирает сумму монет, сортирует покупки и выбирает решение в ситуации.
Новые игры учат сравнивать цену за единицу, считать заработок после расходов и замечать переплату по долгу.
Неверный ответ можно исправить, а пройденные шаги не повторяются при новом входе.
Для шагов с монетами клиент отправляет `answer_value`, для остальных - `answer_index`.
Экспедиции проходят в пять сцен: бюджет, покупка, неожиданный расход, безопасное решение
и накопление. Выбор меняет кошелёк, запас, заботу и итог. Ход содержит `expected_stage`,
поэтому повторный запрос после обрыва сети не тратит монеты дважды. Прогресс хранится
в `task_progress.data` и завершается обычной наградой задания. После финала сюжет можно
пройти снова, чтобы сравнить результаты разных решений.
Каталог мечт — три цели в `domain/rules.py` (`GET /content/goals`). Задания оцениваются по фактам
недели в `domain/services/tasks.py`: урок по верным ответам, накопление по вкладам и копилке,
привычка по дням с уходом, покупка со скидкой по журналу покупок.

## События

Одно событие на игровой день. Выбор детерминирован хешем от игрока, недели и дня.
В профиле можно поставить `event_mode`: `random` (как сейчас) или `escalating` (чаще
события с большим `min_week`). Каталог: `sale_day`, `price_rise`, `sick`, `scam_message`,
`charity`, `crisis`, `new_food`, `guests`, `vaccine`, `pyramid`.

`effects`: `coins` — свободные монеты; `pay` — сначала свободные, иначе копилка;
`cost` — статья плана; `need`; `xp`; `note`; `price_delta` — надбавка к ценам лавки
до конца недели; `sale_percent` — скидка витрины до конца недели; `vaccinate` — недели
без события болезни; `unlock_shop` — товар появляется у этого игрока. В минус уйти нельзя.

`price_rise` поднимает еду на +2 до закрытия недели. `sale_day` даёт скидку до 10% на витрине до конца недели, с округлением вверх.
Прививка (`vaccine`) за 3 монеты закрывает `sick` на 4 недели включая текущую.

## GigaChat

Клиент в `src/infrastructure/ai/gigachat.py`. Схема из документации Сбера: ключ авторизации
обменивается на токен доступа через `POST /api/v2/oauth` (живёт 30 минут, кэшируется),
запросы идут на `https://api.giga.chat/v1` с Bearer-токеном.

Как получить ключ: developers.sber.ru → Studio → проект GigaChat API → Настройки API →
Получить ключ. Ключ показывается один раз, в кабинете не хранится. Скопировать в `backend/.env`:

```
FINIK_GIGACHAT_AUTH_KEY=<Authorization Key>
```

Проверка: `make ai-check` печатает список моделей и одну реплику совы. Пустой ключ
выключает ИИ, сервер работает на заготовленных фразах. Модель по умолчанию
`GigaChat-3-Lightning`; имя модели можно изменить в настройках. Таймаут 8 секунд: если модель не успела, клиент
получает заготовку и поле `source: fallback`. Повтор того же контекста берётся из кэша
(`source: cache`).

Точки `/api/v1/ai/*` возвращают заготовку при недоступной модели. Для отсутствующей недели,
неотвеченного вопроса и повторного ответа возвращается ошибка правил. В текстовом ответе
`source`: `llm`, `cache` или `fallback`. Реплика на главном экране без сети модели — поле
`pet.mood_note` в `GET /state`. Цифры плана мечты считает сервер (в том числе «урезать игры на 2»), модель пишет только совет.
Чат: стоплист (мат, ссылки, номера карт и переданные секреты) и 12 реплик на календарный день. Слово дня кэшируется
на календарный день без привязки к игроку. История совы — `GET /ai/origin`, кэш по виду
и имени. Викторина лавки: сервер считает верный ответ по текущим ценам и обновляет задачи
по календарной дате. Модель может объяснить уже проверенный ответ, но не определяет его правильность.

TLS: у Сбера в цепочке корневой сертификат Минцифры, он лежит в `certs/` и подставляется
клиенту через `FINIK_GIGACHAT_CA_BUNDLE`. Отключать проверку не нужно.

## DeepSeek

DeepSeek можно выбрать как альтернативу GigaChat. Ключ задаётся только в `backend/.env`:

```
FINIK_LLM_PROVIDER=deepseek
FINIK_DEEPSEEK_API_KEY=<ключ>
```

`FINIK_LLM_PROVIDER=auto` выбирает GigaChat при наличии его ключа, затем DeepSeek.
Если ключ выбранного провайдера пуст или сервис недоступен, API возвращает заготовленный
ответ. Запросы DeepSeek используют обычную проверку TLS. Маршрут `/quiz/daily` берёт
вопросы из того же игрового состояния, что `/ai/quiz`; ответ отправляется через
`POST /ai/quiz/answer`.

## Подключение мобилки

Локальная команда выше и конфигурация PyCharm **Finik API** слушают `127.0.0.1:8000`. Android Emulator обращается к этому адресу через `http://10.0.2.2:8000/`.

Для физического телефона в той же сети запустите API с `--host 0.0.0.0` вместо `--host 127.0.0.1`. В Android debug откройте **«Адрес сервера»** на экране знакомства или в профиле, введите IP компьютера и нажмите **«Проверить и подключиться»**. Если введён только IP, приложение добавит HTTP и порт 8000; можно указать полный URL. Адрес сохраняется без пересборки APK. Docker уже слушает `0.0.0.0` внутри контейнера и публикует порт 8000. В Android debug разрешён HTTP; release требует HTTPS и использует фиксированный адрес сборки.

Порядок вызовов с клиента:

1. `POST /api/v1/auth/device` с идентификатором установки `device_id`, IANA-часовым поясом `timezone` и режимом `mode` → токен. Ответ содержит `has_pet`: если false, показать знакомство. Часовой пояс сохраняется при создании игры и не меняется повторным входом.
2. `GET /api/v1/content/goals` — три цели. При знакомстве выбирают цвет совы, аксессуары, доход и цель; `POST /api/v1/pet` передаёт `species=OWL`, `goal_slug`, `look_variant` и `accessories`.
3. Действия возвращают обновлённое серверное состояние. Каталоги, задания и отчёты загружаются отдельными маршрутами. После `POST /api/v1/plan/confirm` можно добавлять свободные монеты в статьи через `/plan/topup` или увеличивать абсолютные суммы через `PUT /plan`; уменьшать статьи и перекладывать деньги нельзя.
4. Демопрофиль использует `mode=demo`. Явный `demo_preset=new|prepared` начинает выбранный сценарий заново; при обычном повторном входе поле опускается, чтобы продолжить демоигру.

Все ответы повторяют модели `core/model` мобилки: `PetOut` ↔ `PetProfile`, `PlanEntryOut` ↔
`PlanEntry`, `TaskOut` ↔ `TaskItem`, `ShopItemOut` ↔ `ShopItem`, `GoalOut` ↔ `SavingsGoal`,
`HistoryWeekOut` ↔ `HistoryWeek`, `ReportRowOut` ↔ `ReportRow`, `BadgeOut` ↔ `Badge`.
Ошибки приходят как `{"error": {"code", "message"}}`, `message` можно показывать ребёнку как есть.
